# Core Feature Guides

How to use each core Scrumooth feature. If you have not set up your team yet, start with the
[Getting Started Guide](../getting-started/README.md).

| Feature                                           | Purpose                                         | Primary Users             |
| ------------------------------------------------- | ----------------------------------------------- | ------------------------- |
| [Product Goal](./product-goal.md)                 | Strategic direction and the backlog's objective | Product Owner             |
| [Product Backlog](./product-backlog.md)           | Ordered work items and prioritisation           | Product Owner, Developers |
| [Sprint Planning](./sprint-planning.md)           | Sprint preparation and commitment               | Scrum Team (facilitated)  |
| [Sprint Board](./sprint-board.md)                 | Daily work tracking (Kanban)                    | Developers                |
| [Daily Scrum](./daily-scrum.md)                   | Daily inspection and adaptation                 | Developers                |
| [Impediment](./impediment.md)                     | Tracking and removing what blocks the team      | Scrum Team                |
| [Increment](./increment.md)                       | Usable, deliverable value produced by a Sprint  | Developers                |
| [Sprint Review](./sprint-review.md)               | Increment inspection and backlog adaptation     | Scrum Team + Stakeholders |
| [Sprint Retrospective](./sprint-retrospective.md) | Process inspection and improvement              | Scrum Team (facilitated)  |

## How These Guides Are Organised

Every feature guide follows the same structure, so you can find the same kind of information in the
same place:

- **Purpose** — what the feature is and why it matters.
- **Key Concepts** — the vocabulary, statuses, fields and roles you need.
- **Practical Guidance** — step-by-step usage.
- **Gates and Enforcement** — the rules Scrumooth refuses to let you break, and how to recover.
- **Best Practices** — habits that make the feature work well.
- **Related Topics** — the guides to read next.
